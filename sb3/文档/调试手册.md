# sb3 调试手册

## 工具

| 工具 | 作用 |
|---|---|
| `01_生成sb3/生成sb3.py` | 生成时内建自检，一步出成品 |
| `02_调试sb3/校验sb3.py` | 对**任意** sb3 做静态结构校验 |
| `03_交互播放器/diag.js` | 浏览器侧诊断：控制台错误、全局变量、VM 状态 |
| `03_交互播放器/capture.js` | 分帧截图 + 记录运行时状态 |
| `03_交互播放器/交互演示.js` | 上传文件、按钮点击、重载的端到端验证 |

## 校验器用法

```bash
python3 02_调试sb3/校验sb3.py 你的项目.sb3
python3 02_调试sb3/校验sb3.py 你的项目.sb3 --json   # 给 CI / 脚本用
```

退出码：`0` 通过，`1` 有错误，`2` 文件打不开。

检查项：

1. ZIP 完整性；根目录必须有 `project.json`，且**不能有子目录**
2. `project.json` UTF-8 无 BOM、JSON 可解析
3. 顶层 4 字段；有且仅有一个舞台且名为 `Stage`
4. 每个 target 必备字段、`costumes` 非空、`currentCostume` 不越界
5. 每个 `md5ext` 文件真实存在；`assetId` == 内容 MD5；`dataFormat` 与后缀一致
6. SVG 根元素为 `svg`、有 `viewBox`
7. blocks：`opcode` 非空、`next`/`parent` **双向一致**且不指向不存在的 ID
8. `inputs` 首位必须是 1/2/3；内联 primitive 类型码必须是 4~13；`fields` 是数组
9. `monitors.id`、积木引用的变量 ID 是否在 target 中声明（警告级）
10. 积木 opcode 前缀疑似扩展但 `extensions` 未声明（警告级）

实测输出：

```
=== 校验: 最小示例.sb3 ===
  · ZIP 条目 3 个
  · project.json 1778 字节，UTF-8 无 BOM
  · meta.semver=3.0.0  vm=0.2.0
  · targets 2 个（舞台 1 + 角色 1）
  · 积木 5 块，next/parent 链与 inputs 编码已校验
  · extensions: 无
=== 结果: 通过（错误 0 / 警告 0）===
```

故意把某块 `next` 改成不存在的 ID，会报：
`× 错误: [Sprite1] move10.next 指向不存在的 不存在`。

## 现象 → 原因对照

| 现象 | 高概率原因 | 先查哪里 |
|---|---|---|
| 完全导不进去 | ZIP 根目录多一层文件夹；`project.json` 带 BOM / 非法 JSON；没有舞台 | 校验器第 1~3 项 |
| 能导入，角色是问号 | `md5ext` 文件不存在；素材没平铺；`assetId` 与内容不符；SVG 缺 viewBox | 校验器第 5~6 项 |
| 能导入，脚本不执行 | `next`/`parent` 断链；脚本没从帽子块起步；扩展 ID 未声明被静默丢弃 | 校验器第 7、10 项 |
| 积木里有空槽 / 默认值消失 | 把 `fields` 和 `inputs` 搞混；阴影状态 1/2/3 写错；primitive 类型码写错 | 校验器第 8 项 |
| 中文变量名 / 监视器乱码 | JSON 读写编码不一致（PowerShell 默认编码常见） | 统一 UTF-8 无 BOM |
| 变量值不对 | 变量 ID 在 `variables`、积木 fields、`monitors.id` 三处没对齐 | 校验器第 9 项 |
| cap 积木后面还有脚本 | `control_stop` 之后不该再接 `next` | 手工检查，静态校验管不到 |

## 推荐闭环

```
改 生成sb3.py 里的 blocks
        ↓
python3 生成sb3.py          ← 生成时自检
        ↓
python3 校验sb3.py 成品.sb3  ← 静态结构
        ↓
浏览器上传 / 官方编辑器导入  ← 反序列化
        ↓
绿旗、点击、看状态栏        ← 运行时语义
        ↓
capture.js / 交互演示.js     ← 留证 + 回归
```

把「**能导入**」当第一验收指标，再叠加玩法。校验器只保证格式合法，**不保证逻辑正确**（比如循环里没等待会卡帧），这一步必须靠真跑。

## 浏览器侧诊断

`diag.js` 会打印：

- 四个 UMD 全局是否加载成功（`VirtualMachine` / `ScratchStorage` / `ScratchRender` / `ScratchSVGRenderer`）
- `window.vm`、`window.__load`、`window.__state` 是否存在
- 页面 `error` / `unhandledrejection` / `requestfailed`
- `window.__state()` 的完整快照

如果看到 `Could not get WebGL context`，说明 `scratch-render` 起不来——本工具包的交互播放器已用 stub renderer 绕过，见 `文档/播放器接口.md`。

## 一个容易误判的点

`校验sb3.py` 说「积木 5 块」，播放器的 `__state().blocks` 却是 **9**。因为 JSON 里的内联 primitive（`[4, "10"]` 这种）不是独立的 block 条目，VM 反序列化时会把它们展开成 shadow 积木对象。两者都对，只是**序列化前**和**运行时**两个视角。
