# 播放器接口

## 起服务

```bash
python3 -m http.server 8123 --directory 03_交互播放器
# 打开 http://127.0.0.1:8123/
```

必须走 HTTP，不能用 `file://`：`vm.loadProject` 要 `fetch` sb3，且 ES 模块/Blob 受同源限制。

## 界面上能做什么

| 控件 | 行为 |
|---|---|
| 📂 选择 sb3 | 上传**任意** sb3，页面自解 ZIP、取素材、重新加载 VM |
| 🚩 绿旗 | 触发所有 `event_whenflagclicked` 帽子块 |
| 👆 点击角色 | 往角色当前位置发一次 mouse down+up，触发 `event_whenthisspriteclicked` |
| ⟳ 重载 | 用当前 buffer 重新反序列化，状态复位 |

状态栏实时显示：角色名、`x/y`、方向、积木数、造型数、活动线程、气泡文字、错误。

**上传任意 sb3 的实现**：`index.html` 内置约 40 行极简 ZIP 读取器，用浏览器原生 `DecompressionStream('deflate-raw')` 解出 `project.json` 与素材二进制，再转成 Blob URL 喂给 `<img>`。所以换项目不需要预先解包素材文件。

## window 上的调试 API

截图脚本与控制台都可用：

| API | 说明 |
|---|---|
| `__load(url)` | fetch 并加载指定 sb3 |
| `__loadFile(File)` | 加载用户选择的本地文件 |
| `__greenFlag()` | 绿旗 |
| `__click(x, y)` | 在画布坐标发一次点击（480×360） |
| `__state()` | 返回运行时状态快照 |
| `__errors` | 页面错误数组 |
| `vm` / `renderer` | 直接访问 VM 与渲染器实例 |

`__state()` 返回：

```json
{
  "ready": true, "name": "Sprite1",
  "x": 10, "y": 0, "direction": 90,
  "bubble": "你好，Scratch！",
  "blocks": 9, "costumes": 1, "threads": 1,
  "errors": []
}
```

实测三段状态：初始 `x=0/方向=90` → 绿旗 `x=10`、气泡出现、线程 1 → 点击 `方向=105` → 重载全部复位。

## 三个截图/诊断脚本

```bash
node diag.js          # 页面诊断，输出全局与错误
node capture.js       # 01 初始 / 02 绿旗 / 03 点击 / 04 纯舞台
node 交互演示.js       # 05 上传后 / 06 按钮绿旗 / 07 按钮点击，并验证重载复位
```

环境变量：`PLAYER_URL`（默认 `http://127.0.0.1:8123/`）、`CHROME_PATH`、`SB3`（交互演示上传的文件）。

`capture.js` 用 `page.waitForFunction(() => window.__state().ready)` 等 VM 真正加载完，再分帧截图，避免截到空白舞台。`交互演示.js` 则是**真实点击 DOM 按钮**并 `setInputFiles` 上传，覆盖用户路径而非只调内部函数。

## 为什么用 stub renderer

沙盒里的无头 Chromium 起不了 WebGL（各种 `--use-gl` / SwiftShader 组合都试过，`getContext('webgl')` 一律返回 null），`scratch-render` 构造时直接抛 `Could not get WebGL context`。

处理方式：

- 用一个 `Proxy` stub renderer 满足 VM 运行时对渲染器接口的调用（`createSVGSkin` / `createDrawable` / `getSkinSize` / `getFencedPositionOfDrawable` / `pick` …）。关键的两个要返回**真实值**：
  - `getFencedPositionOfDrawable(id, pos)` 返回 `pos` 本身，否则 `setXY` 会被强制归零，移动 10 步看不出来
  - `pick()` 返回角色的 `drawableID`，否则点击帽子块不会触发
- 舞台由 Canvas 2D 绘制，数据全部来自 `vm.runtime.targets`：坐标、方向、大小、气泡（`runtime.on('SAY')` 事件）
- **VM 执行是真的**：`vm.loadProject` 完整反序列化 sb3，绿旗/点击走 `vm.greenFlag()` 和 `postIOData`，积木语义、线程调度、`SAY` 事件都由 VM 产生

所以这套适合验证「脚本有没有跑、状态对不对、造型有没有加载」，不适合验证 WebGL 特效、画笔、颜色碰撞、图形效果。

## vendor 里的 4 个文件

| 文件 | 用途 | 当前是否用到 |
|---|---|---|
| `scratch-storage.js` | 素材注册 | ✅ |
| `scratch-vm.js` | VM 运行时（预构建 UMD） | ✅ |
| `scratch-render.js` | 官方 WebGL 渲染器 | 预留：有 WebGL 时可换掉 stub |
| `scratch-svg-renderer.js` | SVG / BitmapAdapter | 预留：配合 `attachV2BitmapAdapter` |

想换成官方渲染器，参考 `04_VM源码/tw-scratch-vm/src/playground/benchmark.js` 第 619~751 行的初始化顺序：`new VirtualMachine()` → `attachStorage` → `new ScratchRender(canvas)` → `attachRenderer` → `attachAudioEngine` → `attachV2BitmapAdapter` → `vm.start()`。
